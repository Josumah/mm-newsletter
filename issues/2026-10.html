This one is mostly about GitHub Universe, which wrapped up October 28-29, and it was a big one. If you only skim one section, make it the first one. The commercial model for Copilot changed, and that's worth a conversation with each of you. Feel free to share this with your team, and if anything catches your eye, let me know and we can dig in.

  • GitHub Enterprise now includes Copilot access, with AI usage billed against your enterprise budget instead of per-seat Copilot licenses.
  • Copilot Fusion is GA, so Copilot picks and combines models for you at the effort level you choose, inside the model policies you already set.

Universe 2026: Copilot is now part of the platform

The theme this year was pretty clear. Copilot is no longer just a separate add-on. It's becoming part of how GitHub Enterprise works, from licensing to where agents run to how code gets reviewed and approved.

GitHub Enterprise now includes Copilot access

Enterprises working with a GitHub or Microsoft account team can now get Copilot included with GitHub Enterprise for every licensed user. Instead of managing Copilot seat counts and usage separately, AI usage is metered from the first request against your enterprise budget, using the policies, alerts, and cost centers you already have. Code completion and next edit suggestions keep working even with no budget, while Copilot Chat, code review, and cloud agents need available budget, and an exhausted budget never removes access. Users without a GitHub Enterprise license can get the same access through Copilot Standalone at $10 per user per month, and Copilot Business and Copilot Enterprise are still available if your current setup works for you. This is available now for GitHub Enterprise Cloud through your account team (self-serve comes later in stages), so this is one we should walk through together. Changelog | What's changing | Billing docs | Keynote recap

Copilot Fusion (GA)

Instead of picking a model for every task, developers pick Copilot Fusion and an effort level (Standard, High, or Max). Fusion decides whether one model handles the task or whether models work together, either by escalating from a cheaper draft to a stronger model or by having one model critique another's work. Fusion only uses models enabled in your enterprise and organization policies, admins can exclude a model from Fusion without disabling it for everyone, and Fusion can be set as the default through enterprise-managed settings. Billing is per model at each model's standard rate, with a limited-time 30% discount on Fusion usage (the VS Code release notes list it through November 30). It's available in VS Code, the Copilot app, Copilot CLI, and JetBrains, and intelligent routing to on-device models is in experimental preview. Changelog | Fusion docs | Admin model controls | Local model routing

One connected Copilot cloud experience (GA)

A Copilot task can now start on github.com, GitHub Mobile, the Copilot app, Copilot CLI, VS Code, Slack, or Teams, and pick back up from any of the others. Sessions run in secure cloud sandboxes that resume where they left off. The cost piece matters here: billing for cloud sandbox usage begins in November 2026 and draws from your included Actions entitlement, which is now one flexible pool for builds, cloud sandboxes, and (on Enterprise Cloud) larger hosted runners. Usage beyond the entitlement follows your existing rates and budgets, so we should take a quick look at your Actions consumption before agent usage ramps. Changelog | Docs

Copilot code review: Max effort and approvals

Copilot code review added a Max effort level (PREVIEW) that runs several review agents across models from different providers, then reconciles their findings into one review. It takes longer and uses more AI credits than Lite or Balanced, and admins can cap the maximum effort at the enterprise, organization, or repository level. Copilot approvals are now GA: when turned on, Copilot's approval counts toward required approvals, gets dismissed when new commits land, and can be limited to specific file paths. Approvals are off by default. Earlier in October, review also picked up REST and GraphQL API support, Balanced became the default effort level, and org owners can now bill reviews to the organization's cost center instead of individual members' quotas. Max and approvals | API support | Billing options | Configure docs

Copilot & AI

  • Copilot Automations grew up. Automations can now be shared across a team instead of running under one person's identity, fire on 24 new events (including code scanning, secret scanning, and Dependabot alerts), chain into multi-step workflows, and use tools from custom MCP servers. The part I'd point every admin to is the new AI credit limits per run, day, week, or month, so a runaway automation can't quietly burn budget. They can also propose improvements to their own prompts based on outcomes, and VS Code can now run them in the cloud when your laptop is closed. Shared automations | Triggers and cost controls | Self-improvement | Docs
  • GitHub Agentic Workflows (GA): Write automation in plain Markdown (issue triage, CI failure analysis, docs updates, test writing) and it compiles into standard Actions YAML. Since these are just GitHub Actions, they reuse your runner groups and policies, and you can power them with Copilot or another coding agent. Changelog | Project docs
  • Agent Merge on pull requests: Select Watch and fix in a pull request's merge box and Copilot fixes failing Actions workflows, merge conflicts, or both in a cloud environment. Pair it with auto-merge and the pull request lands once it's green. Changelog | Docs
  • Connectors (PREVIEW): Developers sign in once to services like Slack, Figma, Notion, and Sentry (26 at launch) and that connection works across the Copilot app, CLI, VS Code, Copilot in the cloud, and Mobile. Admins control which connectors are allowed through the existing MCP allowlist. Changelog | Docs | Enterprise allowlist
  • The Copilot app got Projects, computer use, and image generation. Copilot Projects (PREVIEW) give a multi-repo goal one home, with its context, parallel agents, and results together. Computer use (PREVIEW) lets Copilot work through GUI-only desktop apps that have no API, and image generation can be turned off by policy if that's not something you want in your environment. Copilot app releases | Projects docs | Computer use | Image generation
  • Context that sticks around: GitHub intelligence brings Copilot Memory, repository conventions, and related code history into agent sessions so they don't start from scratch every time. Issue artifacts (PREVIEW) attach plans, research, and HTML diagrams directly to an issue. GitHub intelligence | Memory admin docs | Issue artifacts
  • New models (GA): Claude Haiku 5.5 (fast, high-volume work), Gemini 4 Argon (complex agentic tasks), GPT-6.1 Terra (everyday agentic coding at lower cost than Sol), plus Claude Sonnet 5.5 and GPT-6.1 Sol from the September 28 weekly release. Haiku 5.5, Gemini 4 Argon, and GPT-6.1 Terra are billed at provider list pricing under usage-based billing, so we should check new models against your model policy before turning them on. Haiku 5.5 | Gemini 4 Argon | GPT-6.1 Terra | Models and pricing
  • For platform teams building on Copilot: Dynamic workflows let you define multi-agent orchestration in code across the CLI, app, and SDK. The GitHub Copilot SDK is becoming the Microsoft Copilot SDK, with package names changing in phases, and server-to-server authentication (PREVIEW) lets SDK-based services act on behalf of an org without a signed-in user. Dynamic workflows | SDK transition | Server-to-server auth
  • GitHub in Slack and Teams: @GitHub can now work across multiple repositories in one conversation, and the new Teams app turns notifications into fixes and pull requests without leaving the channel. Slack and Teams | Copilot in Teams

The Copilot harness is now the default for new sessions, and admins got managed-settings controls for sandboxing, permissions, default model, and Fusion tier. Universe releases | VS Code 1.144 notes | September releases

  • Visual Studio: The September update added pull request exploration through the Git agent, bring-your-own model, and a fixer action that hands NuGet vulnerability warnings to Copilot agent mode. Security & Compliance (GHAS)

Security had its biggest month in a while. The common thread is AI doing more of the finding and fixing, with clear billing lines so you can decide where to turn it on.

  • AI Scan for pull requests (GA) and repositories (PREVIEW): AI Scan finds vulnerabilities in languages CodeQL doesn't cover (PHP, Shell, Terraform, Dockerfiles, JSP, Blazor, and more), and the new repository mode scans a whole repo on demand so you can assign the backlog to Copilot. Pull request findings are advisory and won't block merges. Both consume Code Security AI credits (no Copilot license required), with SKU-level budgets available, and security overview now shows AI Scan enablement and remediation metrics. PR scanning GA | Repository scanning | Docs | Metrics
  • Agentic autofix for code scanning alerts (GA): Assign an alert to Copilot and it explores the codebase, proposes a fix, reruns CodeQL to confirm the alert closes, and opens a draft pull request. Heads up on cost: it uses Code Security AI credits plus Actions minutes, and once enabled it replaces the free Generate Fix button on alerts, so we'll want to pick where it's turned on before rolling it out broadly. Changelog | Docs
  • AI secret detection: Push protection (PREVIEW) can now block secrets that don't match a known pattern, like plain passwords, using a classifier that reads the surrounding code. AI-detected secret alerts remain included in Secret Protection and GHAS at no additional charge, while the new push protection check and the Copilot /security-review secret check will consume AI credits. Push protection | Detection model and billing | Docs
  • Public monitoring for enterprises (GA): GitHub watches all of public github.com for your secrets, including leaks from personal forks and public issues, and attributes them back to your enterprise. It's included with Secret Protection at no additional cost, and it now has triage, validity checks, an API, and webhooks. A data residency version is in PREVIEW. GA announcement | Triage and API | Docs
  • Package firewall (PREVIEW): Blocks malicious and risky npm packages before agents, runners, or IDEs install them, with an exception workflow for false positives. It's free during the preview and will move to metered billing (similar to Actions) at GA. Changelog | Docs
  • Dependabot reachability analysis (PREVIEW): For JavaScript and TypeScript, Dependabot now shows whether your code actually calls the vulnerable function, so teams can fix what's reachable first. It runs in a managed Actions workflow with nothing to install. Changelog | Docs
  • Code scanning for AI applications (PREVIEW) and the Copilot app security extension (PREVIEW): Code scanning now flags agent-specific risks like indirect prompt injection and excessive agency on pull requests. The new security extension puts code scanning alerts inside the Copilot app so developers can explain and fix them in one place. AI applications | Security extension | Docs
  • Open source license compliance (GA): Set one enterprise-wide license policy and enforce it on pull requests through a ruleset condition. Available on Enterprise Cloud for repos with Code Security enabled. Changelog | Docs
  • Smaller security updates worth knowing: Anthropic keys are now blocked by push protection by default, with new Salesforce, Supabase, and Lovable detectors. Push attribution (limited PREVIEW) records who actually pushed each commit, risk assessments now show protected vs. unprotected repos, and CodeQL 2.27.2 improved C++, Go, Rust, and JavaScript analysis. Secret detectors | Push attribution | Risk assessments | CodeQL 2.27.2

GitHub Code Quality

There wasn't a new Code Quality launch at Universe, but October filled in some useful admin gaps after the July GA. You can now download Code Quality license usage as a CSV showing every active committer and which repos they touched, which makes it easy for us to spot where turning Code Quality off would free licenses next cycle (it's billed per active committer). Dismissals and reopenings of findings now show up in the audit log, coverage uploads no longer fail CI on branches without a pull request, and weekly scheduled scans now wait for a real push or pull request, so dormant repos stop scanning every week. If your team is thinking about AI-generated code quality more broadly, the "AI Code Hygiene" webinar in the Events section below is a good fit. License CSV | Audit log | Coverage fix | Inactive repos | Cost docs

Enterprise Administration (GHE)

  • GHES security patches: If you run GitHub Enterprise Server 3.18 through 3.22, the October 6 patch releases fix a high-severity issue in secret scanning validity checks that could lead to remote code execution (CVE-2026-96890), plus a medium-severity default-branch bypass. I'd prioritize this one. GHES 3.22 release notes
  • Plugin governance (GA): Enterprises can now require plugins, block plugins, and restrict installs to approved marketplaces through managed settings, across VS Code, Copilot CLI, and the Copilot app. Required plugins install automatically and users can't turn them off. Changelog | Docs
  • Assisted permissions and local sandboxing (GA): Copilot now uses a model to auto-approve clearly safe commands and ask about everything else, and local sandboxes restrict agent access to the filesystem, network, and credentials based on your policies. Together they cut approval fatigue without giving agents free rein. Assisted permissions | Local sandboxing | Sandbox docs
  • Tighter managed settings: Admins can force clients to pull fresh policy at startup, require minimum client versions for governance keys, and (opt-in) attribute Copilot telemetry to a user without capturing prompts. The Copilot model policy REST API (GA) also lets you manage model policies for enterprises, teams, agent apps, and orgs as code, and the global default policy for Copilot features finished rolling out on October 26. Managed settings | Telemetry attribution | Model policy API | Global default
  • Better usage reporting: The usage metrics API now breaks out usage by client (including OpenCode, Claude Code, Codex, and Zed) and names your custom skills, agents, and MCP servers instead of lumping them into "other". If agent activity looked like it dropped recently, updating the IDE fixes it. The impact dashboard also added an opt-in industry comparison, and budgets are now searchable by scope, product, SKU, or user. By client | Named customizations | IDE fix | Industry comparison | Budgets
  • GitHub Apps at the enterprise level (GA): You can install GitHub Apps on the enterprise and use them in place of classic PATs for enterprise governance, security, and admin automation, with new least-privilege permissions. Enterprise installations | Least privilege
  • EMU deprovisioning fix: Between June 1 and June 13, some Enterprise Managed User accounts deprovisioned through SCIM were deleted instead of suspended, so they show up as ghost users. GitHub has published the details and the fix. Changelog

Platform & DevEx

  • Stacked pull requests (GA): Break big changes into smaller pull requests that get reviewed on their own and merge together. GA adds approvals that survive rebases, signed rebase commits, merge queue support for the whole stack, and auto-merge rolling out over the next few weeks. Changelog | Docs
  • Actions multi-cloud compute: Eligible standard Linux 2-core and 4-core jobs can now run on AWS as well as Azure to cut queue times. On Enterprise Cloud this is opt-in under Enterprise settings, so your network team can review it first. Changelog | Runner IP docs
  • Actions workflow lockfiles (PREVIEW): Pin the exact commits behind the action tags you reference, so a moved or compromised tag can't change what runs. Changelog | Docs
  • Merge and rulesets at scale: The async merge API is GA for merging individual or stacked pull requests from automation, and you can now convert all of a repo's branch protections to rulesets in one step. Async merge API | Bulk ruleset migration
  • Runners: The Xcode 27 runner image is GA, and Actions Runner Controller 0.15.0 improves in-place upgrades for large self-hosted fleets. Xcode 27 image | ARC 0.15.0
  • Network allowlist heads-up: If you maintain static allowlists, GitHub added new webhook IP ranges and Actions blob storage hosts, and GitHub App installation tokens are now about 520 characters long. Make sure anything that stores those tokens can handle the new length. Webhook IPs | Actions blob hosts | Token format
  • Reliability: October had several high-impact incidents, including two short write outages on October 7, an Actions, Pages, and webhooks disruption on October 19, and pull request and webhook delays on October 21. GitHub's status history has the details, and the Universe keynote noted the multi-region Azure migration is expected to finish early next year. Status history | September availability report

Deprecations & Migration Notices

  • More Copilot models retire on November 16. Claude Opus 4.8 and Claude Opus 5 move to Claude Opus 5.5, and GPT-5.6 Terra moves to GPT-6.1 Sol or GPT-6 Luna. This follows the October 2 and October 19 removals (including GPT-5.5, GPT-5.4, Gemini 3.7 Flash, Grok 4.5, and Claude Opus 4.7). If an instruction file, automation, or workflow pins one of these, switch it and confirm the replacement is enabled in your model policy. November 16 notice | October 19 removals | October 2 removals | Supported models
  • Secret scanning audit log change on November 12. The business field in secret scanning audit log events switches from the enterprise display name to the enterprise slug. If a SIEM rule filters on the display name, update it to accept both or use business_id. Changelog
  • macOS 14 runner image retired November 2. Move any remaining jobs to a newer macOS image. Changelog
  • CodeQL and Apple's newest toolchain. CodeQL can't do traced builds with Xcode 27 or on macOS 27, and doesn't support Swift 6.4 yet. Use build mode none where it's supported. Changelog | Docs
  • Actions retention now covers checks, workflow runs, and statuses. They're cleaned up on the same schedule as artifacts and logs, so check your retention setting if you rely on old run history for audits. Changelog
  • Push-event email notifications retired October 15. If anyone relied on them, an Actions workflow on push can send the email instead. Changelog
