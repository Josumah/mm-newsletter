James' Curated GitHub Newsletter, August 2026

Read this issue online or browse every past issue in the archive.

Hey everyone, here's my roundup of the GitHub updates that mattered most from July 1 through August 2. The theme this time is pretty clear: agents kept getting more capable, but the controls around cost, policy, quality, and security finally started catching up. That's the shift that makes broader adoption feel practical instead of experimental. If something here lines up with what your team is working through, send it back to me and we'll dig in.

  • Enterprise-managed settings now follow Copilot across more clients, so the same guardrails can cover VS Code, Copilot CLI, the Copilot app, and cloud agent work.
  • GitHub Code Quality is now GA, with quality gates and AI-assisted findings, plus a new standalone pricing model that needs a quick enablement review.
  • AI spend and adoption reporting got much sharper, with cost-center credit pools, per-user budgets, repository metrics, and an impact dashboard.

More agents, tighter controls

Enterprise-managed Copilot settings (GA)

Enterprise-managed settings started the month in VS Code and Copilot CLI, then expanded to the Copilot app and Copilot cloud agent. We can now define approved plugins and marketplaces, control whether users can bypass approval prompts, and set model defaults from one managed configuration. The Copilot app also has its own access policy, so admins can enable it everywhere, turn it off, or let organizations decide without tying that choice to Copilot CLI. Initial GA | Client expansion | App policy | Docs

AI spend controls and adoption reporting

Usage-based billing is easier to manage when included credits, overage, and adoption are not blended into one number. Cost centers can now cap the included AI-credit pool they draw from, while per-user budgets control metered spend and follow assigned users or enterprise teams as membership changes. On the reporting side, repository-level metrics show where coding agent and code review activity is happening, and the impact dashboard groups users by adoption phase so we can target enablement instead of just counting active seats. AI credit pools | Per-user budgets | Repository metrics | Impact dashboard | Budget docs

GitHub Code Quality (GA)

GitHub Code Quality is now generally available on GitHub Enterprise Cloud and GitHub Team. It combines deterministic CodeQL analysis with AI-assisted maintainability and reliability findings, adds code coverage on pull requests, and supports ruleset-based quality gates with an evaluate mode for gradual rollout. This is a standalone paid product at $10 per active committer per month, plus usage-based charges for AI-powered work and the Actions compute used for analysis, so it's worth checking where the preview was enabled before the next bill. GA announcement | Product docs | Billing docs

Copilot & AI

Copilot code review gets skills, MCP, and runtime controls (GA)

Copilot code review can now use repository agent skills and read-only MCP connections to bring team standards, service catalogs, documentation, and other approved context into a review. It also gained a default firewall, independent runner settings, custom setup steps, and the ability to test instruction changes from the pull request's head branch before merging them. GitHub also shared how better review-specific instructions cut average review cost by roughly 20% without reducing review quality, which is a useful reminder that the workflow around an agent matters as much as the model. Skills and MCP GA | Runtime controls | Agent skills docs | Engineering deep-dive

Model choice expanded, and governance changed with it

July added Kimi K2.7 Code, GPT-5.6 Sol, Terra, and Luna, Gemini 3.6 Flash, Claude Opus 5, and Grok 4.5 to Copilot. The bigger admin change is the new default-enablement policy: beginning August 26, newly GA models that are not explicitly configured follow the enterprise or organization default, so teams that want manual approval for every model should disable that policy. Enterprise-team model targeting also entered PREVIEW, letting admins keep a baseline for everyone and grant optional models to role-based or early-adopter groups. Default enablement | Team targeting preview | Supported models

Copilot CLI in Actions no longer needs a PAT

Copilot CLI can now authenticate in GitHub Actions with the workflow's built-in GITHUB_TOKEN, so we can remove a long-lived personal access token from these automations. Organization-owned repositories need the copilot-requests: write permission, and the resulting AI credits are billed to the organization. Cost centers and per-session credit limits give us the guardrails to pair with that simpler authentication model. Changelog | Setup guide

Copilot cloud agent for Linear (GA)

Linear teams can assign an issue to Copilot cloud agent and get progress updates back in the issue while the agent works in an isolated environment and opens a draft pull request. Model selection, custom agents, branch targeting, and steering comments can all be controlled from Linear. Changelog | Cloud agent docs

IDE Updates

VS Code's July releases focused on multi-agent work

VS Code 1.127 through 1.131 made the Agents window easier to use for real project work. Teams can review code beside chat, isolate sessions with worktrees across multiple agent harnesses, fork related conversations, track active subagents, and act on failed checks or review comments without leaving the session. Browser tools are also GA, with isolated agent tabs, explicit sharing for user-opened pages, and admin controls for browser access and network domains. July release summary | Browser tools | Release notes

Visual Studio adds a Copilot SDK-based agent (PREVIEW)

Visual Studio's July update added a new agent built on the Copilot SDK, plus built-in .NET and Azure skills, selected-code review, and organization-level custom instructions. That's a strong parity move for teams that live in Visual Studio and want the same reusable agent patterns showing up elsewhere in the Copilot ecosystem. Changelog | Visual Studio blog | Release notes

JetBrains adds stronger agent and model controls

Copilot for JetBrains added Codex and Claude agent improvements, BYOK support, local sandboxing in PREVIEW, MCP management, and agent debug logs. Later in the month it added OpenTelemetry export, token limits for custom endpoints, built-in model enablement controls, and MCP plus custom-agent support in Claude flows. For mixed-IDE enterprises, those governance and observability controls matter more than simple feature-count parity. Agent update | Governance update | Plugin releases

Enterprise & Security

Agentic security remediation moves into the pull request (PREVIEW)

Agentic autofix can now take a first- or third-party code scanning alert, explore the codebase, propose a fix, rerun the original analysis, and open a validated draft pull request. AI security detections also extend pull request findings to languages and frameworks outside CodeQL's built-in coverage. Both features require GitHub Code Security or GitHub Advanced Security plus Copilot access, and they consume AI credits, while agentic autofix also uses Actions minutes. Agentic autofix | AI security detections | Code scanning docs

Secret scanning public monitoring (PREVIEW)

Public monitoring looks for secrets attributed to your enterprise anywhere in public GitHub content, not just repositories the enterprise owns. Attribution uses enterprise membership and verified domains, which helps security teams catch leaks from personal forks, public issues, or outside open source contributions. It's available at no additional cost for GitHub Enterprise Cloud customers with Secret Protection or Advanced Security. Changelog | Secret scanning docs

Supply chain protections got more automatic

GitHub Actions now holds certain suspicious workflow runs in public repositories until a write-access collaborator approves them, with no setup required. Dependabot malware alerts also gained broader npm, PyPI, and multi-ecosystem coverage through OpenSSF malicious-package advisories. If your teams are getting buried in routine version updates, GitHub also published a practical guide for grouping updates and slowing the cadence without delaying security fixes. Actions protection | Dependabot malware coverage | Supply chain overview | Dependabot guide

  • Worth noting: Secret scanning custom patterns can now be created and managed through repository, organization, and enterprise REST APIs. Dry runs and final publication still happen in the UI. Changelog | REST API docs

Platform & DevEx

Stacked pull requests (PREVIEW)

Stacked pull requests break a large change into smaller, ordered pull requests that can be reviewed in parallel and merged together when ready. Existing branch protections, required checks, and review rules still apply, which makes stacks a practical response to the larger and faster changes agentic development can produce. Changelog | Docs

  • GitHub Actions self-repository syntax: A uses: value beginning with $/ now resolves an action or reusable workflow from the same repository at the exact running commit. That removes the checkout requirement and works cleanly with enterprise policies that require full-length commit SHA pinning. Changelog | Docs

Reliability & Incident Learnings

GitHub had a concentrated run of Actions and core-platform incidents in July, and the resolved Statuspage updates include more detail than the usual service-restored notice. The July 24 network incident affected Actions, Issues, Copilot, Git pushes, and authentication, while a separate database migration issue affected 113,930 pull request creation attempts from 50,904 users. On July 25, two Actions degradation periods tied to Redis maintenance and regional capacity changes peaked with 60% of runs failing with infrastructure errors during the second period. Multi-service incident | Pull request incident | Actions incident

The follow-up work is the useful part: stronger preflight and deployment validation, safer maintenance recovery checks, better autoscaling and memory alerts, certificate-expiry safeguards, more automated failover, and an accelerated data-center network upgrade. Copilot also had several upstream model-provider disruptions; other models generally stayed available, so selecting Auto or another model remained the practical fallback. GitHub incident history

Deprecations & Migration Notices

  • GitHub Models retired on July 30. The playground, model catalog, inference API, and BYOK capability are no longer available. Microsoft Foundry is the recommended path for model-catalog access, while GitHub-native agent workflows continue through Copilot. Retirement notice | Docs
  • Several Copilot models were removed on September 1. The list included Gemini 3.1 Pro, Claude Opus 4.5 and 4.6, Claude Sonnet 4.5 and most 4.6 access, and Raptor Mini. If an instruction file or workflow still pins one of those models, move it to a supported replacement and confirm the replacement is enabled in enterprise policy. Deprecation notice | Supported models
  • The Copilot Billing Preview app retired on August 3. AI usage, exports, cost centers, and budgets now live in GitHub's built-in billing settings and APIs. Retirement notice | Billing docs
